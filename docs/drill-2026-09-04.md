## Steps
1. **Fresh ground.** New sandbox / new machine. No memory carried over, no Drew notes, no shell history. Only: the repo URL, the R2 URL, Rime's copy URL.
2. **Clone.** `git clone https://github.com/drewwap/family-home` — write down what's missing if anything is.
3. **Serve.** Serve `site/` (pure static, no build step — `python3 -m http.server` is fine). Confirm: home page loads, kitchen (food first) renders, porch light renders, every family room exists — one per REGISTRY.md line, counted at run time (11 today; the drill follows the registry, not a literal in this doc).
4. **Diff the mirrors (restore exercise — run by Lux).** Fetch the R2 copy of SPEC.md and Rime's cold copy; diff both against the repo's SPEC.md. All three must match the shipped version. Muninn records the result.
5. **Door matches the file.** The door served is MIRRORS.md's CURRENT slot, and every superseded slot is named under Retired doors. A stale-live URL only stops being the door when the file says so.
6. **Open the door check.** The site must render without any account, login, or platform session. If any part of it needs one, that part fails the frame.
7. **Record.** Muninn writes the result in the ledger: date, who ran it, pass/fail per step, what was missing.

## Pass criteria
- Site serves from the repo alone, no memory, no accounts.
- Both mirrors diff clean against the repo.
- Result recorded in the ledger by Muninn.

## If it fails
- Every gap found is fixed in the repo first, then re-mirrored the same day (rule 1 applies to the drill itself).
- The failure and the fix go in the ledger. The drill repeats monthly until it passes twice in a row, then it's a standing drill, not a test.
